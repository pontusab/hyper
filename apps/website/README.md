# @hyper/website

The site at [hyperjs.ai](https://hyperjs.ai). The marketing page lives
side-by-side with the component registry — same Next.js app, same domain.

- **Framework:** Next.js 16 (App Router) + React 19
- **Styling:** Tailwind CSS v4, single design token set in `app/globals.css`
- **Aesthetic:** plain text document — pure monospace, sharp corners, no
  effects, no syntax highlighting
- **Font:** JetBrains Mono via `next/font`

## Develop

```
bun install
bun --filter='@hyper/website' dev
# → http://localhost:3001
```

## Build

```
bun --filter='@hyper/website' build
bun --filter='@hyper/website' start
```

## Routes

The marketing page lives at `/`. The component registry lives alongside it:

| route                        | what                                    | cache   |
|------------------------------|-----------------------------------------|---------|
| `/registry`                  | browseable component catalog (HTML)     | SWR 5m  |
| `/c/<name>`                  | per-component page (HTML, README, deps) | SWR 5m  |
| `/r/index.json`              | registry index (JSON, wire format)      | SWR 5m  |
| `/r/<name>.json`             | latest manifest                         | SWR 5m  |
| `/r/<name>@<version>.json`   | versioned manifest                      | 1y immutable |
| `/schema.json`, `/schema/*`  | JSON Schema (hyper-config, registry-*)  | SWR 1h  |
| `/healthz`                   | liveness probe                          | none    |
| `/mcp`                       | JSON-RPC 2.0 MCP endpoint               | none    |

The CLI consumes `/r/*` and `/schema/*`. The MCP endpoint is what
Cursor / Claude Desktop / any MCP-aware tool talks to when installing
components conversationally.

## Manifest source

`lib/registry-data.ts` is generated by `tools/build-snapshots.ts` and
gitignored. It's regenerated by:

- the repo-root `postinstall` after every `bun install`
- the website's `vercel-build` hook on deploy

`lib/manifests.ts` reads the snapshot at module level so every request
shares one resolution; Vercel spins fresh function instances on deploy,
which is exactly when we want to pick up new versions.

│   ├── page.tsx                Marketing home

│   ├── registry/page.tsx       Catalog browse UI
│   ├── c/[name]/page.tsx       Per-component page
│   ├── r/index.json/route.ts   Registry index
│   ├── r/[file]/route.ts       <name>.json + <name>@<version>.json
│   ├── schema.json/route.ts    Alias for hyper-config schema
│   ├── schema/[file]/route.ts  All JSON Schemas
│   ├── healthz/route.ts        Liveness
│   └── mcp/route.ts            MCP JSON-RPC endpoint (GET + POST)
├── components/
│   ├── letterhead.tsx          3-line letterhead + bracketed nav
│   ├── hero.tsx                # markdown-style heading + paragraphs
│   ├── code-panel.tsx          Bordered <pre>; optional callout
│   └── footer.tsx              Pipe-separated mono link strip

│   ├── markdown.ts             Tiny README → HTML

│   └── registry-data.ts        Generated snapshot (gitignored)

    └── registry.test.ts        Smoke tests for every route
